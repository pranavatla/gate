How the pieces fit

Tenants call the gateway with a virtual key. The gateway holds the real provider credentials, keeps state in Postgres and Redis, and reports to Grafana.

Two real tenants, two very different trust levels

The same gateway applies different rules to each, expressed as a JSON policy document, like an IAM policy for AI traffic.

One call, whichever model

Tenants send a virtual key and a provider/model name. Switching providers is changing one string.

# any tenant, any provider curl https://gate.atla.in/v1/chat \ -H "Authorization: Bearer $GATE_API_KEY" \ -H "Content-Type: application/json" \ -d '{ "model": "bedrock/global.amazon.nova-2-lite-v1:0", "messages": [{"role": "user", "content": "Hello"}], "max_tokens": 200, "temperature": 0 }'

Every answer carries a status code. Press 200, 402, 403 or 429 to watch the gateway produce it.

400blocked content, personal data or unknown model 401bad or revoked key 413input too large 422malformed request 503no healthy provider

Calls require a tenant key, so this page can't send real requests. Every call that passes the key and contract checks returns an X-Request-ID that maps to a row in the audit log. Prefer JSON? /?format=json or use curl.
